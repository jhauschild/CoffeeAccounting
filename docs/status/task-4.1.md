# Task 4.1: admin login for group admins, TOTP enrolment, stepup_until

Status: done. Commit "admin: v2 login, TOTP enrolment, stepup_until (task 4.1)".

## What changed
- `app/services/admin_auth.py`: v1 login state machine (pending session, `verify_second_factor`, `is_complete`, `ADMIN_TOTP_REQUIRED`) removed. `start_login` now creates a FULL session (`stepup_until = NULL`, 12 h) on a correct password; no TOTP prompt at later logins. New helpers: `has_open_stepup(session, now)`, `enrolment_required(admin)` (= `settings.balance_totp_required and not admin.totp_enabled`), `is_group_admin`, `check_new_password`. `_new_session(db, admin, *, now, stepup_until=None)` (the `verified=` argument is gone). `complete_enrollment` verifies the first code (120 s replay protection kept), enables TOTP, stores 8 hashed recovery codes (returned once) and sets `session.stepup_until = now + STEPUP_WINDOW_SECONDS`; the session is not rotated.
- Group admin login: identifier is a CLI admin username (admin row with `user_id IS NULL`, wins) OR the account username of a user linked to an admin row. For a linked admin the password checked is `users.password_hash`; the admin must be active and the user `status='active'` and `verified_at` set. Same checks apply on every request in `resolve_session`, so an existing group admin session dies when the user is deactivated/unverified. The admin row's own `username` is NOT a login identifier for a linked admin. Rate limiting (5/15 min per username+IP, 15/IP), dummy hash for unknown/unusable accounts (`passwords.verify_dummy`), generic failure message, audit entries all kept. Hashing now goes through `app/services/passwords.py` (cheap parameters in tests via `ARGON2_*`); `admin_auth._hasher` no longer exists. Admin password max length is now 128 (CLI admins keep min 12).
- `create_admin`: only role `global` (role `chair` still raises `InvalidInput`; promotion is task 4.3), refuses a username held by a user (`users.username_normalized`) with `Conflict`. `chairs=` parameter, `set_admin_chairs` and the `set-admin-chairs` CLI command are removed (contract). `reset_password` (CLI) refuses group admins; their password is the account password. `change_password` (own account page) works for both kinds: for a group admin it sets `users.password_hash` under the account policy (`passwords.validate_policy`) and revokes the other admin sessions.
- Web: `/admin/totp` routes and `templates/admin/totp.html` removed. `/admin/login` redirects to `/admin`; `ad.require_admin` redirects to `/admin/totp/setup` while `enrolment_required` (every route except login, `POST /admin/logout` and `GET|POST /admin/totp/setup`, which use `live_admin_session`). `ad.pending_admin` removed. The enrolment page got a sign-out button; strings `admin.totp.*` dropped, `admin.setup.cancel` added.
- `ADMIN_TOTP_REQUIRED` removed from `app/config.py`, `.env.example`, README (table and prose), tests. `BALANCE_TOTP_REQUIRED` replaces it.
- Tests: `tests/admin_support.py` (`make_real_admin(role="chair", chairs=[chair])` now builds a group admin via `factories.make_admin`: a linked member whose ACCOUNT password is the given one; `login_name(admin_id)` gives the identifier to type; `fast_hasher` is a no-op fixture kept for imports). Rewritten: test_admin_auth (34 tests), test_admin_web_login (17), CLI, audit-coverage, route enumeration (new: enrolment-gate test for every route and both admin kinds; "session" policy routes must be exactly logout + the two enrolment routes), security tests.

## Decisions / what later tasks must know
- Demoting a group admin (task 4.3) must set `admin_users.active = False` and revoke the admin sessions but KEEP `role = 'chair'` (group balance history depends on it). `_account_ok` treats an inactive admin row as unable to sign in.
- A group admin is a normal member of the chair, so chair-scoped user lists now include their own account ("Test Member" in the factory); tests that count chair members were adjusted.
- Task 4.2 (step-up): use `admin_auth.has_open_stepup(session, now)`, set `AdminSession.stepup_until`, `_totp_matches(db, admin, code, now)` (replay-protected) and `_consume_recovery_code(admin, code)` (kept for this purpose; no transaction/concurrency test exists any more: the v1 "recovery code single use under concurrency" test was removed with the second-factor login, re-add it for the step-up confirm). `complete_enrollment` already opens the step-up window.
- Task 2.x (user account page / password reset) should revoke admin sessions of a linked admin when the account password changes (`admin_auth.revoke_admin_sessions`); not done here (task 4.1 does it only for the admin account page).
- Task 2.3 (registration) must refuse a username held by a CLI admin (`admin_auth.get_by_username` / `normalize_username`).
- The factory still gives chair admins `password_hash="!"` on the linked user; tests set a real hash on the user (see `make_real_admin`).
- `GET /admin/totp/setup` stays reachable for any live admin (also when TOTP is optional, dashboard/account link) and redirects to `/admin` once enrolled; the recovery-code page is the POST response (shown once).
