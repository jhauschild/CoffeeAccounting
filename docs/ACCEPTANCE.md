# Acceptance report v2 (Definition of Done, PLAN-v2 section 9)

Verified on branch `v2`, commit `32bdd34` (task 7.3), by running the application, not by reading code or quoting the auditor (`docs/status/review-final.md`).
Environment: Linux, Python 3.13.16 (`/home/claude/venv`), no Docker daemon (`docker` CLI 29.8.2 and Compose v5.5.1 exist, `docker info` fails: no socket), no reverse proxy, no route to `postout.lrz.de`.
Method: a clean `git archive HEAD` copy of the repository in a temp directory per instance, SQLite databases there, free local ports. `.env` built with `cp .env.example .env` and edited as the README says (script `docs/status/repro/mkenv.py`).
Two live instances:

- **dev**: `ENVIRONMENT=development`, `http://127.0.0.1:18100`, started as in the README (`uvicorn app.main:app --port 18100`), `MAIL_BACKEND=file` (mails read from the `.eml` files), `BALANCE_TOTP_REQUIRED=true` (the development default is false; set to true so the step-up is exercised).
- **prod**: `ENVIRONMENT=production`, `https://localhost:18443` with real TLS (uvicorn `--ssl-keyfile`/`--ssl-certfile`, the other flags of `scripts/run.sh`, self-signed certificate valid for `localhost` and `127.0.0.1`), `MAIL_BACKEND=smtp` to a local fake TLS SMTP relay (`docs/status/repro/fake_relay.py`: aiosmtpd, STARTTLS required, AUTH only after TLS, built like `tests/test_platform_smtp.py`). **The production code has no injectable trust context outside tests** (`mail.ssl_context_factory` is "tests only"), so the relay certificate is trusted through the OpenSSL environment variable `SSL_CERT_FILE` (the standard trust-store mechanism); certificate chain and host name verification stayed on and no application code was bypassed. The production mail flows therefore ran over verified TLS against the relay; the development instance was used for the mail-independent flows and as a second independent pass of the same checks.

Both instances were brought up exactly as the README describes: `alembic upgrade head`, then the guided `python -m app.cli setup` through a pseudo-terminal (head admin with hidden password prompts, mail login with hidden prompts, first price, test mail).
Driving tools: `curl`, `requests` cookie-jar clients with `pyotp`, headless Chromium via Playwright (pre-installed revision, `playwright install` never run), OpenCV (installed into a scratch directory outside the venv, only to decode QR images), direct SQLite queries (no application code) to cross-check every amount.
Everything is reproducible with the scripts in `docs/status/repro/` (see the end of this file).

## Defects and observations (nothing was fixed)

No defect that blocks use was found. One timing test is flaky under load; the rest are observations.

- **O1 (low, test suite).** `tests/test_final_f6.py::test_wrong_password_and_unknown_user_hash_without_the_write_lock` failed once ("a write waited 0.54s", limit 0.3 s) in a first full run that overlapped with the start-up of the two instances (Argon2 at production cost on the same CPU). It passed in the next two full runs on a quiet machine (1952 passed). The test measures wall-clock waits, so it can fail on a loaded CI machine; consider a more tolerant limit or retry. The application behaviour was confirmed separately: `prod_instance.py` (production Argon2 cost, 6 parallel sign-in loops) passes with 0 of 260 failed.
- **O2 (low, docs vs behaviour).** `.env.example` gives `MAIL_FROM` the example `"Coffee Ledger <coffee@example.org>"`, but only the address part is used: the delivered mails say `From: coffee@tum.de` without the display name (`parseaddr(...)[1]` in `app/services/mail.py`). Harmless; either document it or use the display name.
- **O3 (plan reading).** DoD 3 "no admin screen assigns chairs": no admin screen assigns chairs to admins (there is no such concept any more), but the head admin has a form on the person page to move a person to another chair (head only, audited, no TOTP, plan A7), and every ordinary member can change their own chair at `/account/edit` (a group admin cannot). Both worked as described in the README; the DoD is read as "no admin chair assignment".
- **O4 (environment).** The installed Playwright expects Chromium revision 1243 but only 1194 is pre-installed; `tests/e2e_support.py` and `docs/status/repro/acceptance_browser.py` fall back to `executable_path` of the installed browser (`--no-sandbox`), so the e2e tests run (10 passed, not skipped). A fresh machine with a normal Playwright install is unaffected.
- **O5 (coverage).** The 4 skipped QR tests need `cairosvg`, which the venv lacks; the QR decode check that matters (render in a real browser, decode the pixels) was done here with Chromium and OpenCV. Adding `cairosvg` to `requirements-dev.txt` would let those four tests run (not tried here).
- **O6 (known).** Empty `TRUSTED_PROXY_IPS` behind a proxy still makes all visitors share one rate-limit bucket (finding L2 of the audit); the fix is the documented warning, and the production log showed it. The operator must set the list (README step 4).
- **O7 (known, plan L7).** When the mail login is missing or broken the registration page still says "check your mail" while no mail is sent; the head admin sees the banner on the dashboard and in `mail-status`.
- **O8.** `--role chair` of `create-admin` is still accepted by the argument parser and refused at run time with a clear message (see README commands).
- **O9.** The test run's scripted clients all talked to the server from loopback and set `X-Forwarded-For` to distinct addresses (uvicorn trusts loopback by default), so the rate limits (registration 10 per hour per address, sign-in, forgot, mail cap 30 per hour) did not interfere; they behaved as audited (HTTP 429) in `prod_instance.py`.

Not covered by this run: Docker image build and run, the HEALTHCHECK, the Compose volumes and the `secrets` volume permissions as Docker applies them, the Caddy and nginx examples, the real `postout.lrz.de` handshake and LRZ policy, a real phone camera or in-app QR scanner (cookie-jar differences), printing the QR codes, a forced 500 page in production (covered by pytest), the proxy log redaction in a real proxy, the privacy page's legal sufficiency (the plan asks for a word with the data protection contact), the lock file on the real image Python.

Test-harness side effects: `opencv-python-headless` was installed into a scratch directory outside the venv (`pip install --target`) only to decode QR images; nothing in the repository or the venv was changed. No application code was changed.

## Reproducing this run

From the repository root (commands in this order; `WORK` must not exist):

```bash
bash docs/status/repro/acceptance_up.sh WORK                     # git archive copies, certificate, fake relay, both instances via `setup` (pty)
python docs/status/repro/acceptance_v2.py --name dev  ...        # DoD 1 to 8 over HTTP, SQL cross-checks (arguments in the script header)
python docs/status/repro/acceptance_v2.py --name prod ...
python docs/status/repro/acceptance_browser.py --name dev|prod ...   # Chromium journeys and QR decoding (needs cv2 via --cvdeps)
bash docs/status/repro/acceptance_cli.sh WORK                    # alembic, bootstrap-admin, admin and price commands, qr, docker compose config, pip-audit
python docs/status/repro/acceptance_ops.py WORK                  # DoD 9, start-up refusals, smoke.sh, backup and restore
bash docs/status/repro/acceptance_backup_extra.sh WORK           # retention and restore on a copy
bash docs/status/repro/acceptance_down.sh WORK
```

Helpers: `fake_relay.py` (TLS SMTP relay), `pty_run.py` (runs a command in a pseudo-terminal, answers prompts, fails if a typed secret is echoed), `mkenv.py` (`.env` from `.env.example`).
